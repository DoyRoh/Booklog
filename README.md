# 책숲

아이의 독서를 부모·교사, 그리고 책을 추천하는 기관·크리에이터가 함께 기록하고 넓혀가는 어린이 독서 플랫폼.

Next.js(App Router) + TypeScript + Supabase 기반. 자세한 제품/스키마 설계는 `CLAUDE.md`를 참고하세요.

이 저장소의 `legacy/index.html`은 서비스형으로 확장하기 전의 개인용 프로토타입("유안이 독서기록")으로, 디자인 시스템과 UI 참고용으로만 남겨둔 것이며 빌드에는 포함되지 않습니다.

## 로컬 실행 방법

### 1. 의존성 설치

```bash
npm install
```

### 2. Supabase 프로젝트 준비

1. [supabase.com](https://supabase.com)에서 새 프로젝트를 생성합니다.
2. `.env.example`을 복사해 `.env.local`을 만들고, Supabase 프로젝트의 **Settings → API**에서 값을 채웁니다.

   ```bash
   cp .env.example .env.local
   ```

   ```env
   NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
   ```

3. `supabase/migrations`의 마이그레이션을 프로젝트에 적용합니다. [Supabase CLI](https://supabase.com/docs/guides/local-development/cli/getting-started)를 사용하는 경우:

   ```bash
   npx supabase login
   npx supabase link --project-ref <project-ref>
   npx supabase db push
   ```

   CLI를 쓰지 않는다면 Supabase 대시보드의 **SQL Editor**에서 `supabase/migrations` 안의 `0001_init_schema.sql`부터 `0005_phase4_groups.sql`까지 순서대로 실행해도 됩니다.

4. **Authentication → Providers**에서 이메일 로그인이 켜져 있는지 확인합니다. (기본값으로 켜져 있습니다.) 로컬 개발 중에는 **Authentication → Email**에서 "Confirm email"을 꺼두면 가입 즉시 로그인 테스트를 할 수 있습니다.

### 3. 카카오 책 검색 API 키 발급 (Phase 2)

바코드 스캔·ISBN 조회로 책 표지/제목/저자를 자동으로 가져오는 데 씁니다.

1. [카카오 개발자](https://developers.kakao.com)에 로그인 후 **내 애플리케이션 → 애플리케이션 추가하기**로 앱을 하나 만듭니다.
2. 만든 앱 → **앱 키**에서 **REST API 키**를 복사합니다.
3. `.env.local`에 추가합니다.

   ```env
   KAKAO_REST_API_KEY=여기에-REST-API-키
   ```

   `NEXT_PUBLIC_` 접두사가 없는 서버 전용 값입니다 — 브라우저에는 절대 노출되지 않고, `/api/books/lookup` 라우트에서만 사용됩니다. 별도 권한 설정 없이 REST API 키만 있으면 책 검색 API를 바로 쓸 수 있습니다.

### 4. 개발 서버 실행

```bash
npm run dev
```

[http://localhost:3000](http://localhost:3000)에서 확인합니다. `/`는 `/today`로 리다이렉트되며, 하단 5탭(오늘/책장/기록/추천/더보기) 네비게이션이 보여야 합니다.

### 5. 회원가입 → 온보딩 → 로그인 → 로그아웃 확인

로그인하지 않은 상태로 `/today` 등 탭 경로에 들어가면 자동으로 `/login`으로 이동합니다. 로그인했지만 온보딩(역할 선택·약관 동의·아이 등록)을 마치지 않았다면 자동으로 `/onboarding`으로 이동합니다.

1. `/signup`에서 이메일/비밀번호로 가입합니다.
2. (이메일 확인을 켜둔 경우) 받은 메일의 링크를 클릭해 계정을 확인합니다.
3. `/login`에서 로그인하면 `/onboarding`으로 이동합니다.
4. **역할 선택**(부모/교사/큐레이터) → **약관 동의**(필수 이용약관, 선택 음성녹음) → (부모인 경우) **아이 등록**(이름, 생년월일, 아바타) 순서로 진행하고 "시작하기"를 누르면 `/today`로 이동합니다.
5. 온보딩을 마친 뒤 `/login`이나 `/signup`에 다시 들어가면 자동으로 `/today`로 리다이렉트되는지 확인합니다.
6. 하단 탭의 **더보기**에서 로그인한 이메일이 보이고, **로그아웃** 버튼이 동작하는지 확인합니다.

### 6. RLS 수동 검증

서로 다른 두 계정(예: 부모 A, 부모 B)으로 각각 아이(`children`)를 등록하고, `child_guardians`로 연결한 뒤:

- 부모 A 계정으로는 자신이 등록한 아이와 독서기록만 조회/수정되어야 합니다.
- 부모 B 계정으로 부모 A의 아이 데이터에 접근하면 빈 결과(RLS에 의해 차단)여야 합니다.
- 교사 계정으로 학급형 그룹을 만들고 부모 계정이 가입 승인을 받은 뒤, `teacher_reading_view`를 통해서만 최소한의 독서기록 컬럼이 보이는지 확인합니다.

이 시나리오는 실제로 로컬 Postgres(mock auth 스키마)에 두 마이그레이션을 적용해 부모A/부모B/교사 세 계정으로 검증했습니다. 그 과정에서 다음 두 가지 버그를 실제로 발견해 고쳤습니다:

1. **RLS 무한 재귀**: `child_guardians`와 `group_members`가 "같은 그룹/아이의 다른 보호자 보기" 같은 정책에서 자기 자신을 다시 조회하고, `groups` ↔ `group_members`가 서로를 참조하면서 순환이 생겨 `infinite recursion detected in policy` 오류가 났습니다. → `SECURITY DEFINER` 헬퍼 함수(`is_child_guardian`, `has_group_role`, `is_approved_group_participant`)로 내부 조회가 RLS를 다시 타지 않도록 고쳤습니다.
2. **가입 신청 자체가 막히는 문제**: `group_members` INSERT 정책이 `groups` 테이블을 직접 조회해 `join_policy`를 확인했는데, approval형 그룹은 승인되기 전엔 애초에 SELECT로 보이지 않아 신청 자체가 거부됐습니다. → `group_join_policy()` 헬퍼 함수로 RLS를 우회해 `join_policy`만 조회하도록 고쳤습니다. (그룹 존재 여부·가입방식만 노출되며 민감 정보는 아닙니다.)

**알려진 한계(Phase 3~4에서 다룰 것)**: `reading_records.group_id`는 보호자가 자유롭게 값을 넣을 수 있고, 실제로 그 그룹에 승인된 상태인지는 검증하지 않습니다. 즉 이론적으로 부모가 자신의 독서기록에 임의의 `group_id`를 지정하면, 그 그룹의 교사가 `teacher_reading_view`로 승인되지 않은 아이의 기록까지 볼 수 있습니다. 독서기록에 그룹을 연결하는 실제 기능이 들어오는 Phase 3~4에서, 승인된 멤버십을 검증하는 트리거나 서버 로직으로 막아야 합니다.

### Phase 1 추가 검증: 권한 상승 방지

`users` 테이블은 로그인한 사용자가 자기 행(row)을 수정할 수 있게 되어있는데(온보딩에서 역할을 저장하려면 필요), 값 제한이 없으면 누구나 자기 `role`을 `'admin'`으로 바꿔치기할 수 있는 구멍이 됩니다. 로컬 Postgres에서 실제로 `update users set role = 'admin' where id = auth.uid()`를 시도해 RLS가 막는지(`new row violates row-level security policy`), 그리고 `role`을 `parent`/`teacher`/`curator`로 바꾸는 정상 온보딩 업데이트는 성공하는지 확인했습니다.

### 7. Phase 2 확인: 책 등록 (바코드 스캔 / ISBN 직접 입력)

**책장** 탭 → **"+ 책 등록"**에서:

1. **카메라로 바코드 스캔**: 실제 스마트폰 브라우저로 접속해야 카메라 권한 요청까지 제대로 테스트됩니다 (노트북 웹캠도 가능하지만, 실사용 시나리오는 폰 카메라입니다). `localhost`는 보안 컨텍스트로 취급되어 로컬 개발 중에도 카메라 권한 자체는 동작하지만, 폰에서 접속하려면 로컬 서버를 배포하거나(Vercel) 같은 와이파이에서 `http://<PC의 사설IP>:3000`으로 접속해야 합니다 (`npm run dev` 실행 시 뜨는 "Network:" 주소).
2. **ISBN 직접 입력**: 카메라 없이도 바로 테스트 가능합니다. 아무 책 뒷면의 13자리 숫자(ISBN)를 입력하면 카카오 책 검색 API로 표지·제목·저자를 가져와 미리보기를 보여줍니다.
3. **중복 방지**: 이미 등록된 ISBN을 다시 입력하면 카카오 API를 다시 부르지 않고 기존 책 정보로 바로 기록 단계(아래)로 넘어갑니다 (`book_isbns.isbn`이 DB 레벨에서도 `unique` 제약이라 이중으로 막혀 있습니다).

`KAKAO_REST_API_KEY`를 설정하지 않으면 조회 단계에서 에러가 뜨는데, 정상입니다 — 위 3번 단계를 따라 키를 발급해 넣어주세요.

### 8. Phase 3 확인: 독서기록 + 다자녀 전환

**아이 등록·전환** (더보기 탭):

1. 더보기 탭에 로그인한 이메일, 역할, 등록된 아이 목록이 보이는지 확인합니다.
2. **"+ 아이 추가"**로 두 번째 아이를 등록합니다 (이름/생년월일/아바타).
3. 아이 카드를 탭하면 "선택됨" 표시가 옮겨가는지 확인합니다 — 이게 지금부터 책장·기록에 표시될 아이입니다.

**독서기록 남기기** (책장 탭 → "+ 책 등록"):

1. 책을 스캔/입력해서 조회하면, 이제 미리보기 화면에 **평점(1~5) · 기분 · 즐겨찾기 · 부모 메모** 입력이 함께 뜹니다.
2. "기록 남기기"를 누르면 그 책이 **현재 선택된 아이**의 독서기록으로 저장됩니다.
3. **책장** 탭에 표지가 그리드로 뜨는지, **기록** 탭에 평점·기분·메모가 담긴 목록으로 뜨는지 확인합니다.
4. 더보기에서 다른 아이로 전환한 뒤 책을 하나 더 등록하면, 책장/기록이 그 아이 것만 따로 보이는지 확인합니다 (같은 부모 계정이라도 아이별로 책장이 분리됩니다).

로컬 Postgres로 이 시나리오(아이 두 명, 각각 다른 책 등록, 전환 시 책장 분리)와 보안 검증(다른 부모의 아이로 `active_child_id`를 바꿔치기하면 RLS가 막는지)을 실제 쿼리로 확인했습니다.

**아직 없는 것**: 사진·음성 기록 (`reading_records.photo_url`/`voice_url` 컬럼은 이미 있지만, 파일 업로드용 Supabase Storage 버킷 설정과 촬영/녹음 UI는 다음 단계에서 추가합니다).

책 등록 화면에는 **"ISBN 없이 제목만으로 등록"** 옵션도 있습니다 — 카카오 책 검색에 없는 오래된 책·수제책 등을 위한 경로로, `book_isbns`에 아무것도 남기지 않고 `books.source`를 `manual`로 저장합니다.

### 9. Phase 4 확인: 그룹 + 추천도서

**그룹 만들기** (교사/큐레이터 계정, 추천 탭 → "+ 그룹 만들기"):

1. 그룹 이름·유형(유치원/학교/도서관/가족/커뮤니티/크리에이터)·가입 방식(승인제/공개)을 정해 만듭니다.
2. 만들면 자동으로 그 그룹의 운영자(교사/큐레이터)로 등록되고, "추천도서"라는 기본 목록이 함께 생깁니다.
3. **승인제** 그룹이면 그룹 상세 화면에 **초대 코드**(6자리)가 보입니다 — 이 코드를 학부모에게 공유합니다.

**부모가 가입하기** (추천 탭):

- **승인제 그룹**: "초대 코드로 참가하기"에 코드를 입력하면 그룹 이름이 뜨고, "가입 신청" 누르면 대기 상태로 들어갑니다. 승인 전에는 그 그룹의 추천도서가 안 보여야 합니다.
- **공개 그룹**: "둘러보기" 목록에 바로 뜨고, "팔로우" 누르면 승인 없이 즉시 가입됩니다.

**교사가 승인 + 책 추가** (그룹 상세 화면, 운영자로 접속):

1. "가입 승인 대기"에 뜬 아이 이름을 승인하면, 그 부모 쪽에서 그룹/추천도서가 보이기 시작하는지 확인합니다.
2. "책 추가"에서 **책 제목으로 검색**(카카오 API, ISBN 없이 키워드 검색)하거나 "검색에 안 나오는 책이에요"로 수동 입력해 추천도서 목록에 책을 추가합니다.

로컬 Postgres로 이 전체 시나리오(승인제 그룹 생성 → 초대 코드 조회 → 가입 신청 → 승인 → 추천도서 조회, 그리고 공개 그룹 즉시 팔로우)와 격리 검증(가입하지 않은 다른 부모 계정에는 그룹·추천도서가 안 보이는지)을 실제 쿼리로 확인했습니다.

**아직 없는 것**: 그룹당 추천도서 목록은 1개로 고정(다중 목록 관리 없음).

### 10. 책장 보기 방식 (책등 / 전면) + 검색

**책장 탭:**

1. 상단 검색창에 책 제목이나 작가 일부를 입력하면 실시간으로 걸러지는지 확인합니다.
2. 검색창 오른쪽 토글로 **전면 책장**(표지 그리드, 기존 방식)과 **책등 책장**(색깔별 책등이 나란히 꽂힌 모양)을 전환합니다. 마지막으로 고른 보기 방식은 브라우저에 저장되어 다음에 열 때도 유지됩니다.
3. 책장 상단에 "OO의 발자국 N개"로 지금까지 읽은 책 수가 표시되는지 확인합니다.

### 11. Phase 5 확인: 독서숙제

**교사가 숙제 만들기** (그룹 상세 화면, 운영자로 접속, 추천도서가 최소 1권 등록돼 있어야 함):

1. "숙제" 섹션의 **"+ 숙제 만들기"**를 누르고 제목·안내문구·기간(선택)을 입력합니다.
2. **읽을 책 고르기**에서 추천도서 목록 중 이번 숙제에 포함할 책을 체크합니다(최소 1권 필수).
3. 필요하면 **"+ 질문 미션"**(예: "가장 기억에 남는 장면은?")이나 **"+ 낭독 미션"**을 추가합니다. 음성 녹음은 아직 준비 중이라 낭독 미션은 안내 문구만 뜨고 실제 녹음 기능은 없습니다.
4. "숙제 만들기"를 누르면 그룹 상세 화면의 "숙제" 목록에 바로 뜨는지 확인합니다.

**부모가 숙제 확인하기** (오늘 탭, 아이가 그 그룹에 승인된 상태여야 함):

1. 숙제 기간(시작일~종료일) 안이면 오늘 탭에 그 숙제가 그룹 이름과 함께 뜹니다.
2. 각 책 옆의 **"다 읽었어요"**를 누르면 평점 없이 바로 독서기록이 생기고(5초 안에 기록한다는 핵심 목표 반영), 책장/기록 탭에도 나타나는지 확인합니다. 나중에 기록 탭에서 평점·메모를 채워 넣을 수 있습니다.
3. 질문 미션이 있으면 답을 입력하고 저장 → "수정"으로 다시 바꿀 수 있는지 확인합니다.
4. 숙제 기간이 지나거나 아직 승인 대기 중이면 오늘 탭에 뜨지 않아야 합니다.

로컬 Postgres로 `assignment_mission_responses` 테이블의 RLS(보호자는 자기 아이 답변만 CRUD, 교사는 자기 그룹 답변을 조회만 가능, 다른 부모는 전혀 접근 불가)와, "다 읽었어요" 기록 후 `assignment_completion` 뷰가 실제로 완료로 바뀌는지를 실제 쿼리로 확인했습니다.

### 12. Phase 6 확인: 교사 / 큐레이터 대시보드

**교사 계정**: 더보기 탭 → "교사 대시보드로 가기"(또는 로그인 후 오늘 탭에서 안내). 운영 중인 그룹마다 멤버 수·승인 대기 건수·숙제별 완료 현황(완료 X/Y)이 보이는지 확인합니다.

**큐레이터 계정**: 더보기 탭 → "큐레이터 대시보드로 가기". 발행한 그룹마다 팔로워 수와 추천도서 권수가 보이는지 확인합니다.

두 대시보드 모두 `role`이 다르면(예: 부모 계정으로 `/teacher` 접속) "교사/큐레이터 계정에서만 볼 수 있는 화면이에요" 안내만 뜨고 데이터는 안 보여야 합니다.

### 13. 사진·음성 업로드 확인

`supabase/migrations/0007_phase_storage.sql`과 `0008_remove_teacher_voice_access.sql`을 순서대로 SQL Editor에서 실행해야 합니다 — 0007이 비공개 Storage 버킷 `reading-media`를 만들고 RLS를 걸고(버킷 생성도 SQL로 되고, 별도로 대시보드에서 만들 필요는 없습니다), 0008이 교사에게 줬던 낭독 미션 녹음 조회 권한을 다시 뺍니다.

**책 등록에 사진·음성 첨부** (`app/library/add` 기록 단계):

1. "사진 첨부"로 이미지를 고르면 미리보기가 뜨고, "기록 남기기"를 누르면 실제로 업로드된 뒤 저장됩니다.
2. "음성 기록"은 온보딩에서 "음성 독서기록 녹음 및 보관에 동의합니다"에 체크했을 때만 보입니다 — 체크 안 했다면 안 보이는 게 정상입니다. 마이크 권한을 허용하고 녹음 후 "저장 중..." 없이 바로 "다시 녹음" 버튼과 재생 컨트롤이 뜨는지 확인합니다.
3. 저장 후 **기록** 탭에서 그 책 카드에 사진 썸네일과 오디오 플레이어가 뜨는지 확인합니다. 새로고침해도 계속 재생 가능해야 합니다(매번 새 서명된 URL을 발급합니다).

**낭독 미션 녹음** (오늘 탭, 교사가 낭독 미션이 포함된 숙제를 만든 뒤):

1. 음성 동의를 한 부모 계정으로 오늘 탭에 들어가면 낭독 미션에 "낭독 시작" 버튼이 보입니다.
2. 녹음 후 재생까지 확인하고, 페이지를 새로고침해도 저장된 녹음이 그대로 재생되는지 확인합니다.
3. 같은 미션을 다시 녹음하면 이전 파일이 새 파일로 교체되는지(누적되지 않는지) 확인합니다.
4. 음성 동의를 안 한 부모 계정으로는 "온보딩에서 음성 녹음에 동의하지 않으셨어요"만 뜨고 녹음 버튼 자체가 없어야 합니다.

로컬 Postgres로 `storage.objects`를 최소 스키마로 모킹해 보호자는 자기 아이 폴더 전체를 CRUD, 교사는 어떤 녹음·사진에도 접근 불가, 다른 부모는 완전 차단(조회 0건, 업로드 거부)까지 실제 쿼리로 확인했습니다. (처음엔 교사에게 낭독 미션 녹음 조회 권한을 줬었는데, "교사는 뭘 읽었나/언제 읽었나만 알면 된다"는 판단으로 다시 뺐습니다 — 0008 마이그레이션.)

### 14. 질문 은행 확인

`supabase/migrations/0009_book_questions.sql`을 SQL Editor에서 실행해야 합니다 — 레거시 앱의 범용 질문 10개를 시드 데이터로 넣습니다. AI API 호출이 전혀 없는 정적 질문 목록이라 비용이 들지 않습니다.

**책 등록 화면** (`app/library/add` 기록 단계):

1. 부모 메모 입력란 위에 "오늘의 질문"으로 질문 하나가 무작위로 뜨는지 확인합니다.
2. "다른 질문"을 누르면 다른 질문으로 바뀌는지, "+ 질문 추가"로 새 질문을 적어 저장하면 그 질문이 바로 표시되는지 확인합니다.

**숙제 만들기 화면** (그룹 상세, 운영자로 접속):

1. "+ 질문 미션"을 추가하면 입력란 아래에 질문 은행의 질문들이 칩(버튼) 형태로 뜨는지 확인합니다.
2. 칩을 누르면 입력란이 그 텍스트로 채워지는지, 입력란에 은행에 없는 새 질문을 직접 타이핑해서 숙제를 만들면 다음번에 그 질문도 칩 목록에 나타나는지 확인합니다.

로컬 Postgres로 `book_questions` RLS를 확인했습니다 — 로그인한 사용자(부모/교사 구분 없이)는 전체 질문을 조회할 수 있고, 자기 질문만 추가·삭제할 수 있으며, 다른 사람 명의로 질문을 넣거나 남의 질문을 지우는 시도는 모두 막힙니다.

### 15. 책 상태(읽고 싶어요/읽는 중/다 읽음) 확인

`supabase/migrations/0010_reading_status.sql`을 SQL Editor에서 실행해야 합니다.

**책 등록** (`app/library/add`):

1. 기록 단계 맨 위 "지금 상태"에서 세 버튼 중 하나를 고를 수 있는지 확인합니다(기본값은 "다 읽었어요").
2. "읽고 싶어요"나 "읽는 중이에요"를 고르면 평점·기분·즐겨찾기·오늘의 질문 섹션이 사라지고, 저장 버튼 문구도 "읽고 싶은 책으로 저장"처럼 바뀌는지 확인합니다. 사진·음성·메모는 그대로 남아 있어야 합니다.

**책장 탭**:

1. 상단 필터 칩(전체/읽고 싶어요/읽는 중/다 읽음)으로 걸러지는지 확인합니다. 검색·책등/전면 보기와 함께 써도 정상 동작해야 합니다.
2. "읽고 싶어요"/"읽는 중" 책 카드에만 작은 배지가 뜨고, "다 읽음" 책에는 배지가 없는지 확인합니다.
3. "OO의 발자국 N개"가 "다 읽음" 책만 세는지 확인합니다 — 읽고 싶은 책을 추가해도 숫자가 그대로여야 합니다.

**기록 탭**:

1. 기록 카드를 누르면 뜨는 수정 모달에서 상태를 언제든 바꿀 수 있는지 확인합니다(16번 항목 참고). 바꾸면 책장 탭의 필터·배지에도 반영돼야 합니다.

**숙제와의 연동** (교사가 이 책을 필독서로 낸 숙제가 있는 경우):

1. 아이 책이 "읽고 싶어요"나 "읽는 중"이면 오늘 탭·교사 대시보드에서 그 책이 아직 "완료"로 안 잡혀야 합니다.
2. 상태를 "다 읽음"으로 바꾸면 그제서야 완료로 잡히는지 확인합니다.

로컬 Postgres로 `reading_records.status`를 want→reading→done 순서로 바꿔가며 `assignment_completion` 뷰의 `completed` 값이 매번 맞게 바뀌는지, 그리고 다른 부모가 남의 아이 기록 상태를 바꾸려는 시도가 막히는지(0건 UPDATE) 확인했습니다.

### 16. 레거시 대조 점검 반영 확인

`supabase/migrations/0011_teacher_view_children.sql`을 SQL Editor에서 실행해야 합니다 — 교사가 아이 이름을 못 보던 버그(승인 대기 목록 등)를 고칩니다.

**기록 수정** (책장 탭 카드 클릭 / 기록 탭 카드 클릭 / 오늘 탭 최근 기록 클릭):

1. 아무 책이나 클릭하면 하단에서 수정 모달이 올라오는지 확인합니다.
2. 상태·평점·기분·즐겨찾기·메모를 바꾸고 "저장"을 누르면 실제로 반영되는지(책장/기록 탭에 새로고침 후 보이는지) 확인합니다.

**기록 탭 개편**: 검색창에 제목/작가 일부를 입력하면 걸러지는지, 월별로 묶여서 "2026년 8월 · N권" 형태로 보이는지, 상단에 "총 N권 · 평균 O점" 요약이 뜨는지 확인합니다.

**책장 탭**: 카드를 클릭하면 수정 모달이 열리는지, 검색/상태 필터 옆의 정렬 드롭다운(최신순/제목순/작가순)이 동작하는지 확인합니다.

**오늘 탭**: 상단에 읽은 책/이번 달/최장 연속 통계 카드가 뜨는지, 숙제 아래에 "최근 기록"이 최대 5권 뜨고 클릭하면 수정 모달이 열리는지 확인합니다.

**배지**: 책장 탭 헤더의 "발자국 N개 · 배지 보기"를 눌러 `/badges`로 이동 → 지금까지 기록/연속/재독/사진·음성 여부에 맞는 배지가 색으로 켜져 있는지 확인합니다(레거시처럼 이모지가 아니라 리본 아이콘 하나로 통일돼 있습니다).

**책 등록 흐름 통합**: 책장 탭 "+ 책 등록" 또는 기록 탭 "책 기록하기"로 들어가면, 이전처럼 선택 화면이 따로 없이 바로 "제목·저자 검색 / 바코드 스캔 / ISBN 입력" 토글이 뜨는지 확인합니다. 제목 검색으로 부모도 책을 찾을 수 있는지(이전엔 교사만 가능했음) 확인합니다.

**교사/큐레이터 전용 메뉴** (교사·큐레이터 계정으로 로그인):

1. 하단 탭이 오늘/책장/기록이 아니라 **대시보드 / 아이 관리 / 숙제 / 그룹 / 더보기**(교사) 또는 **대시보드 / 그룹 / 더보기**(큐레이터)로 바뀌는지 확인합니다. 로그인 직후 잠깐 부모 탭이 보였다가 바뀌는 건 정상입니다(역할 확인 중).
2. **아이 관리** 탭에서 운영 중인 그룹별로 아이 이름과 아바타, 숙제 완료 현황(완료 X/Y)이 뜨는지 확인합니다 — 이전에는 RLS 버그로 이름이 비어 보였을 수 있는 부분입니다.
3. **숙제** 탭에서 여러 그룹에 걸친 숙제가 그룹 이름과 함께 한 목록으로 뜨는지 확인합니다.

로컬 Postgres로 새 `children` 정책(교사는 자기 그룹 아이 이름 조회 가능, 무관한 부모는 여전히 차단)을 확인했습니다.

### 17. 하단 탭 개편 + '기록 남기기' 확인

마이그레이션 없이 화면 구성만 바뀐 변경입니다.

1. 아무 탭 화면에서든 우측 상단에 "더보기" 아이콘이 항상 떠 있는지 확인합니다(로그인/회원가입/온보딩 화면에는 안 보이는 게 정상).
2. 하단 탭이 **오늘 / 책장 / 기록 / 추천 / 배지**로 5개인지, "더보기"가 하단 탭에서 빠졌는지 확인합니다.
3. 우측 상단 "더보기"를 눌러 기존 더보기 화면(프로필/아이 관리/로그아웃 등)이 그대로 뜨는지 확인합니다.
4. 하단 탭의 "배지"를 눌러 `/badges`로 바로 이동하는지, 헤더가 "배지"(다른 탭과 같은 스타일)로 바뀌었는지 확인합니다.
5. 책장 탭 "+ 기록 남기기" 또는 기록 탭 "책 기록하기" 버튼으로 들어가면 화면 제목이 "기록 남기기"로 뜨는지 확인합니다("책 등록"이라는 문구가 어디에도 안 남아있어야 합니다).
6. 교사/큐레이터 계정으로 로그인해 하단 탭이 각각 4개(대시보드/아이 관리/숙제/그룹), 2개(대시보드/그룹)로 줄고, 우측 상단 "더보기"로 대시보드 링크·로그아웃에 여전히 접근 가능한지 확인합니다.
